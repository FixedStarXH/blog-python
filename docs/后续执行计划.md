# Blog Python 后续执行计划

以《需求规格说明》和 Go 项目、现有前端为依据。每步完成实现、相应验证和兼容差异记录后，按模块单独提交并推送，展示结果后暂停，等待继续。已经实现但尚未完整验收的功能列入对应步骤。

| 顺序 | 工作内容 | 完成与验收标准 | 状态 |
| --- | --- | --- | --- |

| 2 | 投稿与后台文章管理 | 复核草稿、待审、驳回重提、排期、发布、批量操作和回收站；验证状态转换、作者权限、事务和公开可见性。 | 待执行 |
| 3 | 分类、标签、专栏 | 对照增删改查、排序、引用关系、作者权限和前端页面；验证已删除数据和关联一致性。 | 待执行 |
| 4 | 用户与权限管理 | 对照用户筛选、角色、禁用/启用和登录状态；验证编辑与管理员边界、令牌撤销及异常路径。 | 待执行 |
| 5 | 图库与文件上传 | 验证上传、列表、删除、文件类型与大小、路径安全、持久化和前端操作，覆盖失败和遗留数据。 | 待执行 |
| 6 | 站点运营功能 | 核对友链、站点设置、每日一言、首页统计、仪表盘、趋势、RSS 和 Sitemap；验证公开信息和敏感配置隔离。 | 待执行 |
| 7 | 审计与可观测性 | 补齐审计目标及请求结果，检查业务失败与并发时的记录行为；核对日志、请求 ID、健康和依赖就绪探针。 | 待执行 |

| 9 | 缓存、限流和计数一致性 | 检查多实例缓存失效、热点回源、Redis 故障恢复、限流退化与浏览/点赞的并发一致性；记录可复现的负载和结果。 | 待执行 |

| 11 | AI 问答与额度 | 完善额度配置、上游超时和错误、流中断的处理及前端反馈；通过模拟服务覆盖异常，再使用真实服务联调。 | 待执行 |
| 12 | 分层与接口模型 | 按用例将路由中的业务事务逐步下沉到 Service，补齐必要的请求与响应模型；保持调用契约和现有测试。 | 待执行 |
