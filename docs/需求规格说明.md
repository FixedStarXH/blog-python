# Blog System Python 需求规格说明

## 1. 文档目的

本文件定义 Blog System 从 Go 后端迁移到 Python 后端时需要保留的产品功能、接口行为、数据规则和运行要求。它以 `blog-go` 的路由、模型、服务逻辑和前端调用为基准。迁移期间，Go 项目作为行为参考；Python 项目达到本文件的验收条件后，才视为可替换版本。

## 2. 项目目标

构建一个可独立部署的多用户博客 CMS，包含公开博客、投稿和审核、后台内容管理、缓存与安全能力、AI 摘要及基于文章的 RAG 问答。现有 React/Vite 多页面前端继续使用，Python API 需保持现有 URL、请求字段、响应字段和认证约定，避免为了迁移后端而重做前端。

## 3. 用户与权限

| 身份 | 权限 |
| --- | --- |
| 游客 | 浏览已发布的公开文章、分类和标签；发表评论；点赞；访问 RSS/Sitemap；使用受限的公开 AI 总结和问答 |
| 普通用户（role=1） | 游客能力；注册、登录、管理个人资料与密码；创建和管理自己的投稿；上传文章图片；维护自己的专栏 |
| 编辑（role=2） | 普通用户能力；审核投稿；管理文章、评论、分类、标签、图库、友链、站点设置；查看仪表盘与审计日志 |
| 管理员（role=3） | 编辑能力；管理用户状态与角色；清空审计日志；访问管理员专属诊断接口 |

认证接口必须区分未登录（401）与权限不足（403）。后台路由执行认证和角色校验。普通用户只能读取、修改和删除自己的投稿；编辑可管理所有文章。

## 4. 功能需求

### 4.1 公开博客

- 首页数据：置顶文章、精选文章、分类、标签、专栏推荐、站点统计和每日一言。
- 文章列表：按关键词、作者、分类、标签筛选；支持分页及最新/热门排序；返回 `list`、`total`、`page`、`pageSize`。
- 文章详情：仅公开已发布文章；返回作者、分类、标签、摘要、正文、阅读量和点赞量。私密文章未解锁时只返回 `needPassword=true`，不能泄露正文。
- 私密文章：通过密码校验后返回正文；公开导出接口拒绝导出私密文章。
- 文章导航、归档、热门文章、Markdown 导出、RSS 2.0 和 Sitemap。
- 浏览量与点赞按访客 IP 或登录身份去重；并发更新不得丢失计数。
- 公开评论只展示已审核通过的记录，支持楼中楼回复和评论点赞。

### 4.2 账号和投稿

- 注册字段：用户名、邮箱、密码；用户名与邮箱不可重复，密码只保存安全哈希。
- 登录接受用户名或邮箱，返回 access token（2 小时）和 refresh token（7 天）。刷新时旧 refresh token 单次轮换；登出、改密和账号禁用应撤销有效 refresh token。
- 个人信息接口支持查询和修改昵称、头像、简介；密码修改需验证旧密码。
- 投稿状态：草稿 `0`、已发布 `1`、待审核 `2`、已驳回 `3`、定时发布 `4`。作者修改被驳回的投稿后重新进入待审核；到达发布时间后，定时任务将状态从 `4` 转为 `1`。
- 投稿字段包括标题、正文、摘要、封面、来源链接、分类、标签、私密密码和发布时间。
- 作者只能操作自己的文章。删除采用软删除并进入回收站，已删除文章不得出现在公开查询、搜索、RSS、Sitemap 或 RAG 检索中。

### 4.3 后台 CMS

- 文章：分页筛选、查看、创建、编辑、审核通过、驳回并记录原因、发布、转草稿、置顶、精选、定时发布、软删除、回收站和批量操作。
- 分类和标签：创建、编辑、删除、排序、重复名称校验、文章数统计。被文章引用时按 Go 原版规则处理，不允许产生悬空关联。
- 评论：分页筛选、通过、驳回、改状态、删除和批量审核。
- 用户：分页检索、按角色筛选、禁用/启用、角色变更；禁止普通用户给自己提权。
- 图库：上传、分页查询和删除；扩展名白名单为 jpg/jpeg/png/gif/webp，校验文件内容，限制 5 MiB，使用随机文件名并防止路径穿越。
- 友链：完整 CRUD、启用状态和排序；公开接口只返回启用记录。
- 站点设置：读取和更新 KV 设置；公开接口不得泄露密钥类配置。
- 仪表盘：文章、用户、评论等统计；支持近 7/30 天浏览趋势。
- 审计日志：记录后台写操作及认证尝试的操作者、角色、动作、请求方法、路径、目标、来源 IP、结果和时间；日志只追加，只有管理员可清空。

### 4.4 AI 与 RAG

- Chat 与 Embedding 使用独立 OpenAI 兼容配置，服务地址、密钥、模型名和向量维度均来自环境变量。
- 支持摘要、润色、单篇文章总结、后台单篇/全量索引、索引状态和公开问答。
- 仅索引已发布且非私密文章。正文按约 500 字切块、约 50 字重叠；所有新向量成功后再事务替换旧索引，失败时保留旧索引。
- 文章转草稿、转私密或删除时清理其索引；公开文章变更后异步重建，连续更新合并，失败有限次重试。
- 问答按问题向量与文章块做余弦相似度，选取前 5 个片段作为上下文；单篇问答必须先确认文章公开。
- SSE 流式回答沿用前端识别的 `data: {"delta":"..."}` 和 `data: [DONE]` 格式；支持经校验的多轮历史，不接受客户端提供的 system 消息。
- 对 AI 接口按 IP 限流并实施每日额度控制；鉴权失败、限流、超时和服务错误不得静默伪装成成功回答。只有明确不支持 Embedding 时才允许走全文降级。

### 4.5 统一接口约定

- 保留 Go 前端使用的 `/api` 路径和 HTTP 方法，包括兼容别名（如 `/api/archive` 与 `/api/archives`、后台上传路径）。
- JSON 成功响应为 `{ "code": 200, "message": "success", "data": ... }`。业务错误使用相应 HTTP 状态与 `{ "code": ..., "message": ..., "data": null }`。
- SSE、RSS、Sitemap、Markdown 导出和静态文件使用各自内容类型，不套 JSON 信封。
- 字段名保持前端的小驼峰形式，如 `accessToken`、`coverImage`、`categoryId`、`pageSize`。
- 未实现的 `/api/*` 路径返回 JSON 404，不回退到 HTML 页面。

## 5. 数据实体

Python 数据模型至少涵盖以下 Go 实体及其关系：

| 实体 | 关键内容 |
| --- | --- |
| User | 用户凭证、资料、角色、状态、软删除时间 |
| Article | 内容、作者、分类、专栏、状态、发布时间、私密信息、计数、软删除时间 |
| Category / Tag / ArticleTag | 分类、标签和文章多对多关系 |
| Column | 作者专栏和启用状态 |
| Comment | 文章、用户/游客、父评论、审核状态、点赞数 |
| ArticleView / ArticleLike | 去重指纹和访问时间 |
| Setting / Link / Image | 站点 KV、友链、图库元数据 |
| ArticleChunk | 文章块、向量、模型版本、维度、内容哈希和索引时间 |
| AuditLog | 后台操作审计记录 |
| RefreshToken | refresh token 轮换、撤销和到期时间 |

生产数据库使用 MySQL 8。SQLite 仅用于本地开发和隔离测试。模型迁移由 Alembic 管理；不得依靠 `create_all` 修改已有 Go 数据库结构。

## 6. 非功能要求

- **安全**：密码哈希；JWT 固定算法和 token 类型校验；生产密钥强制从环境变量读取；上传校验文件头；评论输出转义；可信代理策略明确；敏感配置不得回显。
- **并发与一致性**：文章点赞/浏览去重；缓存计数最终写回；RAG 索引事务替换；审计记录不因业务失败丢失。
- **缓存**：Redis 承担文章列表/详情/归档缓存、refresh token 白名单或撤销、限流、AI 额度和阅读量缓冲。Redis 暂不可用时按功能定义降级，不能让核心文章读写失败。
- **可观测性**：结构化请求日志、`/health` 存活探针、`/ready` 依赖就绪探针；生产关闭调试信息。
- **部署**：Docker Compose 启动 Python API、MySQL、Redis；多阶段构建 React/Vite 前端；上传目录持久化；容器以环境变量配置。
- **兼容**：前端现有 URL、响应结构、权限和状态值保持一致；差异必须记录在迁移说明中并获得确认。

## 7. 验收标准

1. 本文列出的公开、用户、编辑和管理员接口都有明确路由、Schema、权限和响应定义。
2. Python 项目可通过 Compose 全新启动，数据库迁移、种子数据、静态前端和上传目录均工作。
3. 前端核心流程可联调：注册/登录/刷新、投稿审核、评论审核、用户管理、图片上传、站点设置、RAG 问答。
4. 针对 Go 行为建立接口兼容清单；迁移验收逐条对照状态码、字段、权限和关键副作用。
5. 软删除、私密文章、refresh 轮换、上传校验、评论审核、RAG 隐私边界有自动化回归覆盖。
6. 不将尚未验证的压测数字或功能标记为已完成。
